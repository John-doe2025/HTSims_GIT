i am working on a heat transfer solver of a uav nacelle the solver includes 6 files and is completely in python the config.py file includes all the configurations of components in the nacelle as well as the material properties of every node, the environmental_model.py includes the external radiation code such as solar flux albedo radiation planetary radiation etc, fetch_data.py file is just to use the api to collect solar flux data corresponding to time of the day and store it in a csv file, physics_models.py includes all the physics involved in the solver like formulas for radiation conduction convection, forced and natural, simulation.py file includes all the heat transfer equations of every node the DT/dt equation for calculation of heat flux of each node, at last there is post_processing.py file which includes most of the code for generating data and plots  

okay so the geometry is in such a way that inside the nacelle there are 6 battery packs in cuboidal form arranged as battery front top then bottom then middle top and bottom and then rear ones the top and bottom batteries are sepearted by the middle plate and there is a plate at the top and bottom of the batteries defining the three plates then there are 4 bulkheads one in front of battery front then bh2 is in middle of batt front and batt middle and so on there is another component which produces heat called the esc which is placed on the esc mount which is attached to the bulkhead 1 the materials and properties of every node is present in the config.py file

out of the two sims file simulation.py would give normal results in most cases, the idea where we implemented simple logic of following Q_obj1_obj2 = constant*(temp_obj2 - temp_obj1) and then adding up all the Q in net_q which made proper sense but due to the increasing amount of nodes sometimes the solver behaves radically in the initial phases and then settles down to a steady state, right now its assumed that the reason is huge differences in mC of different nodes as well as thermal shocks which the solver is sometimes unable to handle, we are still unaware of the effect of this instability on the solver results at steady state though because falling sharply to low temps and then going back up to steady state may cool down the nacelle, disrupting our results, simulation_final.py is just an experimental file to debug simulation_fix file
